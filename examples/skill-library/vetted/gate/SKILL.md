# 🚪 gate — 统一门禁脚本（示例脱敏版）

## 一、解决什么
将"任务是否完成/合格"的判断从口头与 AI 汇报交给机器：
1. **统一门禁入口** — 按声明式 manifest 逐条执行检查，硬门禁失败即阻断，软门禁失败留 WARN 供人工确认。
2. **基线快照** — 变更前冻结基线 → 变更后 diff，只阻断"新增失败"，杜绝"这问题之前就有"的甩锅。

## 二、何时使用
- 生产变更前/后、跨 Agent 产出验收、任何"能写成脚本判定"的质量红线。

## 三、检查类型
| type | 判定 | 参数 |
|------|------|------|
| `cmd_exit` | 命令返回 0 即通过 | `cmd` |
| `file_exists` | 路径存在 | `path` |
| `keyword` | 文件包含/排除关键字 | `path`,`needle`,`exclude` |
| `json_path` | JSON 路径取值==期望值 | `path`,`jq`,`expect` |
| `sha256_match` | 文件哈希前缀匹配期望值 | `path`,`expect` |

## 四、纪律
- 能写成脚本判定的，别留在 Rule/prompt 里让人解释执行。
- 硬门禁宁少不多；改 manifest = 改规矩唯一入口，不动脚本。

## 五、安全边界（示例）
纯本地判定，不访问网络，不读取身份与凭据文件，不执行不可信输入命令。符合共享库分级 🟢 可入库。
